# little-proxy — заметки для агентов

Минималистичное Win32-приложение на Rust: TCP-трафик процессов, чей **полный путь exe** совпал с
одной из регулярок (без учёта регистра), заворачивается в SOCKS5/HTTP CONNECT-прокси. Мимо
прокси трафик целевых процессов не уходит: их UDP и соединения, открытые до запуска, режутся.
Второй вид правил — **домены**: HTTP/HTTPS (порты 80/443) любого процесса к адресам, которые DNS
вернул для домена или его поддомена, тоже уходит в прокси.

## Сборка и проверки

- `cargo build --release` → `target/release/little-proxy.exe` (единственный файл; WinDivert вшит,
  CRT линкуется статически через `.cargo/config.toml` — на чистой Windows нет `VCRUNTIME140.dll`).
  Только x64: драйвер `WinDivert64.sys` на ARM64 не работает.
- `cargo test --release`, `cargo clippy --release --all-targets` — должны быть чистыми.
- Тесты живут в lib (`src/lib.rs`): у бинарника манифест `requireAdministrator` (см. `build.rs`),
  поэтому `[[bin]] test = false`.
- Живой тест требует прав администратора: правило `\\curl\.exe$`, локальный SOCKS5,
  `curl https://ifconfig.me` — IP должен быть IP прокси, в журнале строка `curl.exe → ifconfig.me:443`.
  Доменные правила — так же, но без `match=` и с доменом `ifconfig.me`; `curl --doh-url
  https://1.1.1.1/dns-query …` должен падать (DoH заблокирован).
- Если exe запущен, сборка падает с «Access is denied» — сначала закрыть программу.
- Bash-heredoc в этом окружении превращает `\\` в `\` — код с обратными слешами (регулярки, пути)
  правь через Edit/Write, не через `cat <<EOF`.

## Устройство

- `src/main.rs` — окно на чистом Win32 (`windows-sys`), без ресурсов; журнал забирается таймером.
  Значок в трее есть всегда (подсказка — статус); сворачивание прячет окно, левый клик по значку
  возвращает его, правый — меню «Открыть / Запустить·Остановить / Выход». После перезапуска
  Проводника значок восстанавливается по `TaskbarCreated`. Крестик (`WM_CLOSE`) при работающем
  перехвате тоже прячет окно в трей (первый раз — всплывающая подсказка; выход — «Выход» в меню
  значка), при остановленном — закрывает программу.
  Если значок не добавился (`Shell_NotifyIconW` вернул отказ), окно не прячется — иначе его не
  вернуть. Одна копия: повторный запуск находит окно класса `LittleProxy` (`FindWindowW`), шлёт ему
  `WM_APP+2` («покажись») и выходит.
  Кнопка «Проверить» сверяет запущенные процессы (`EnumProcesses` + полный путь) с правилами из
  поля (`Matcher::running`) и пишет в журнал каждый подошедший процесс: имя, PID и командную
  строку (`NtQueryInformationProcess`, класс 60; если не прочиталась — путь exe).
  Внизу окна — ссылка на GitHub (SysLink, `InitCommonControlsEx(ICC_LINK_CLASS)`, открытие через
  `ShellExecuteW`).
- `src/divert.rs` — FFI к WinDivert 2.2.2 через `LoadLibrary`; `vendor/windivert/*` вшиты
  `include_bytes!` и распаковываются рядом с exe. Раскладка `WINDIVERT_ADDRESS` — 80 байт, флаги
  битовыми полями (Outbound — бит 17).
- `src/engine.rs` — два хэндла WinDivert:
  - SOCKET (sniff): события bind/connect/listen/accept/close → кеш «локальный порт → владелец»;
  - NETWORK `outbound and !loopback and (tcp or udp)`: решение по каждому пакету.
  TCP целевого процесса A:a→B:b отражается (NAT в стиле streamdump) в B:a→A:P и вбрасывается как
  входящий на локальный приёмник порта P; ответ A:P→B:a превращается в B:b→A:a. Ключ NAT —
  (IP адресата, порт клиента). Для SYN владелец всегда сверяется с таблицей IP Helper (гонка
  событий и переиспользования портов). Записи NAT живут 30 с после конца сессии.
  - третий хэндл (только при непустом списке доменов) — NETWORK `inbound and !loopback and
    udp.SrcPort == 53`: ответы DNS перехватываются (не sniff — чтобы адрес был известен до того,
    как приложение начнёт соединение), адреса A/AAAA запоминаются на TTL (не меньше 5 мин, не
    больше суток), пакет возвращается без изменений. При запуске — `ipconfig /flushdns`.
  - при доменных правилах блокируются: TCP/UDP на порт 853 (DoT/DoQ), порт 443 к известным IP
    серверов DoH (`dns::DOH_IPS`) и к адресам из ответов DNS на имена DoH (`dns::DOH_HOSTS`),
    UDP 443 (QUIC) к адресам доменов из списка. Собственный процесс доменными правилами не
    заворачивается (его подключения к вышестоящему прокси).
- `src/dns.rs` — разбор ответа DNS (вопрос, A/AAAA, сжатие имён) и `Domains` (домен + поддомены).
- `src/proxy.rs` — приёмник (IPv4+IPv6 на одном порту), SNI из ClientHello для порта 443
  (имя хоста уходит в прокси вместо IP), SOCKS5 (без/с логином) и HTTP CONNECT (Basic).
  `external_ip` запрашивает `https://1.1.1.1/cdn-cgi/trace` через вышестоящий прокси (TLS —
  `native-tls`, т.е. SChannel) и возвращает внешний IP и страну.
- Запуск двухшаговый: «Запустить» разбирает настройки (`engine::Setup::new` — ошибки сразу), затем
  в фоновом потоке проверяет прокси через `external_ip`; окно забирает результат по таймеру
  (`mpsc`, без `PostMessage`: во время модального меню трея `APP` занят). Перехват
  (`Engine::start`) включается, только если прокси ответил; иначе в журнале причина. Пока идёт
  проверка, поля и кнопка заблокированы, статус — «Проверка прокси…».
- `src/procs.rs` — таблицы TCP/UDP с PID, сброс старых IPv4-соединений целей (`SetTcpEntry`),
  сопоставление процесса правилам.
- `src/config.rs` — `little-proxy.ini` рядом с exe: `proxy=<url>`, строки `match=` и `domain=`. URL прокси
  (`socks5://логин:пароль@хост:порт`, `http://…`, без схемы — SOCKS5, %-кодирование логина и
  пароля) разбирает `Upstream::parse`; его ошибки не содержат учётных данных. Пароль хранится
  открытым текстом.

## Ограничения (осознанные)

- UDP не проксируется, а блокируется (QUIC откатывается на TCP). DNS целевых процессов идёт через
  системный резолвер (служба Dnscache), т.е. не от их PID — не перехватывается.
- Дочерние процессы не наследуют правило: они должны совпасть сами.
- Старые IPv6-соединения целей не сбрасываются, а отбрасываются (повиснут до таймаута).
- При запуске пересоздаётся правило брандмауэра `little-proxy` (вход разрешён для exe): иначе
  отражённые «входящие» соединения к приёмнику режутся.
- Если exe упал или остановлен — перехвата нет, трафик идёт напрямую.
- Правило не должно совпадать с самим прокси-клиентом пользователя (иначе петля); собственный
  процесс исключён всегда. То же для доменов: сервер стороннего прокси-клиента не должен быть в
  списке.
- Доменные правила видят только DNS по UDP через сеть: ответы по TCP и от локального резолвера на
  loopback (127.0.0.1) не разбираются. Соединения к доменам, открытые до запуска, и адреса из
  собственного кеша браузера (DNS не спрашивался после запуска) идут напрямую. DoH на сервер вне
  встроенных списков не блокируется. Для порта 80 имя хоста в прокси не передаётся — только IP.
